# KhanhhNeLatex

An original, deliberately small Prism-inspired LaTeX workspace. React JavaScript frontend, Express 5 API on Cloudflare Workers' native Node HTTP adapter, Drizzle ORM and Cloudflare D1. No Prism code/assets, image uploads, server compilation, or polling.

The home screen follows the publicly visible Prism Projects dashboard's high-level structure: dark project surface, narrow navigation, search, list/grid views, sortable document rows, Import and New actions. The workspace uses a blue-charcoal source surface, muted line numbers, a rounded file tab and teal/yellow/purple syntax. Compact dark toolbars, preview surroundings, status/log/loading surfaces, navigation and dialogs form one consistent visual system, following the user's preference for dark chrome throughout. Native PDF paper and content retain their compiled colors without filters or a replacement renderer. All UI code, branding, icons and copy are original; no reference images are distributed. The signed-in live editor was inaccessible, so this is evidence-based visual alignment, not a claim of pixel-perfect parity. Unsupported collaboration controls and the marketing image's overlapping panels/backdrop are deliberately omitted. Open a project to write, or use `/#workspace` to reopen the latest device draft directly. Monaco and pdfTeX begin loading only when the workspace opens, not while browsing projects.

## Local development

Requires Node 26.12+ (or a cf-supported Node version), npm, and a Chromium-compatible browser with WebAssembly, Workers and IndexedDB.

```powershell
npm ci
npm run db:local
npm run build
npm run preview
# http://127.0.0.1:8787 -- real Cloudflare Workers runtime + local D1
```

In another terminal, `npm run dev` optionally serves Vite HMR at port 5173 and proxies API requests to the local Worker. Local API mutations require the configured origin: use the main 8787 preview for sign-in/cloud-save testing. Compiler/package assets are included locally. Documents with explicit Google font declarations may download fonts as described below; other compilation remains self-hosted.

```powershell
npm test
npx playwright install chromium webkit
npm run test:e2e
```

The browser tests include a real WASM PDF compile/export, worker cancellation/error handling, local persistence, text-only import validation, responsive layout, session cookies, ownership/CSRF checks and revision conflicts.

Mobile regressions run Chromium and WebKit with the iPhone 13 Pro profile at 390x844 portrait and 844x390 landscape, plus shortened browser-toolbar and keyboard-height viewport simulations. These are emulations, not physical iPhone/Safari keyboard or notch measurements. Mobile chrome reserves platform safe-area insets without disabling zoom; source/title/search inputs use at least 16px text, and reduced-height pages and dialogs keep bottom actions scrollable. Set `MOBILE_ARTIFACTS` to an existing local folder to capture audit screenshots while running `npx playwright test mobile.spec.js`.

On phones the combined bar hides with the reading controls and returns with **Show reading controls**.

This device preference preserves your saved sidebar/split sizes and does not compile or save documents. While hidden, the compact **More document actions** popover provides New, Import and Delete; Escape or a click outside dismisses it. Mobile retains its independent document drawer.

Narrow screens retain the document drawer and open documents in **Read** mode with an initial compiled PDF. **Export PDF**, **Export .tex** and the viewer's **Open PDF** action are available while reading. **Edit** exposes source, title editing and Save to account; **Compile & read** returns to the preview after a successful compile. A failed or cancelled compile retains the last good PDF. Tapping or scrolling can hide reading controls; the always-visible **Show reading controls** button restores them without relying on another gesture. **Copy private link** copies the current workspace permalink; device-only drafts still open only on the device that has them, and account permalinks require the owner's sign-in. Choose **Share read-only link** to create or reuse an account-backed link that lets recipients read and compile the latest saved source without editing it. Monaco does not load until Edit is first opened on mobile; after that the single editor remains mounted for that document to preserve undo and selection across mode switches. Phone landscape reserves more room for the PDF; very short keyboard-height viewports remain scrollable.

Sidebar document cards give titles the full width and wrap long names without truncation. Availability icons, the last-edited date and the compact account-version button sit on a second row inside each card. Select anywhere else on a card to open its device draft (or its account document when not on this device); the separate account button retains a 44px touch target and keyboard focus.

- One text-only UTF-8 `.tex` file per document, maximum 100,000 characters; imports also limited to 400 KB. No image, font, binary or other source uploads.
- Pending account saves/deletions never lock the workspace: create, switch, edit, compile or delete other documents while requests wait. Each sidebar item shows its pending operation; deletion keeps the item until the account confirms, then selects a neighbour only if that item is still open. Requests for the same document are serialized/coalesced, with at most two document operations running at once. Delete uses one confirmation; a failed deletion retains the draft and offers **Retry delete**. Account-save failures show a non-blocking **Retry sync** message, without polling.
- IndexedDB device drafts save after a 300 ms pause and flush on document switches/visibility changes. Pending/failed saves are explicit; pending writes warn before navigation. Export `.tex` for backups, especially before clearing browser data or changing devices. Device drafts are not encrypted; use a trusted personal device.
- Selecting a document opens `/documents/<title-slug>/<8-character-code>`. Refresh and browser Back/Forward reopen it; renaming replaces the cosmetic slug without changing the code. A stale slug resolves by code and is corrected. Device-only links work only where that draft is stored; account links require the owner's sign-in and never enable public sharing. Existing cloud documents receive collision-free numbered codes in the additive migration; older device drafts receive codes on first load and adopt their linked account code before CRDT synchronization.
- There is one logical document per unique code, not a device version and an account version. Device drafts save automatically; signing in or reconnecting synchronizes eligible drafts with the same account document. While signed in, edits synchronize after an 800 ms pause; **Save to account** also synchronizes immediately. Drafts already owned by another account never upload to the current account. Ctrl/Cmd+S only forces a fresh compilation, never an immediate save. Sign-in is optional for editing, compilation and exports.
- On sign-in, an untouched first-visit sample is removed from this device instead of uploaded when the account already has another document; if open, it is replaced by the most recently edited account document. An empty account keeps the sample. Source is compared exactly (including whitespace) and title changes count as edits; timestamps and CRDT encoding differences alone do not. Older unmarked drafts with the exact sample title/source receive the same treatment. Explicitly created or imported drafts, already-linked documents and modified samples keep normal synchronization.
- Text uses the pinned, locally bundled Yjs sequence CRDT. Monaco changes become range operations, not whole-document replacements. Offline concurrent insertions/deletions converge when replicas synchronize, without a conflict dialog; equal-position insertions use Yjs's deterministic operation order. Same-device tabs merge through atomic IndexedDB writes and BroadcastChannel notifications. No polling, WebSocket provider, external document service or runtime package fetch is used; a quiet, already-connected device receives other-device edits on open, save, sign-in or reconnect, not as live collaboration.
- D1 retains plain source in `documents.source` (`TEXT`) for exports/compilation, alongside nullable base64 CRDT state. Every operation is owner-scoped. Bounded compare-and-swap retries merge overlapping account writes atomically. The older revision-based API stays compatible and maps its source edits into existing CRDT history. Up to 100 account documents.
- Pre-CRDT documents bootstrap deterministic history from their initial source. Identical legacy copies do not duplicate text. If same-code legacy copies have no shared history and differ, common complete prefix/suffix lines are retained once and both differing middle spans are kept in lexical order (or once when one contains the other), then the device adopts the account's canonical history. This conservative migration does not infer author intent; overlapping legacy changes may need ordinary text cleanup, but neither differing span is silently discarded.
- Only the active document keeps an in-memory Yjs replica. Saves encode consolidated state with Yjs garbage collection; deleted character payloads are released but operation identities are retained for old offline replicas. Encoded updates are bounded to 768 KB before base64, and merged source remains limited to 100,000 characters. These limits fail visibly and retain the device draft rather than resetting history (which would break convergence). Export source and create a new document if history fills. IndexedDB quota or network failures remain visible; a merged document exceeding the source limit leaves both original replicas unchanged.
- Accounts use case-insensitive 3-32 character usernames and 8-128 character passwords. Salted scrypt (N=16384,r=8,p=1), hashed random 256-bit session tokens, seven-day HttpOnly/SameSite=Strict cookies (Secure on HTTPS), strict mutation origins, parameterized Drizzle queries, request limits and D1-backed auth throttling. No password reset/recovery is provided in this minimal version.

### Read-only sharing

Choose **Share** in the desktop document toolbar or **Share read-only link** in the mobile More actions sheet. Sign in first; sharing saves the latest draft to your account before creating a link. The dialog reuses an existing link, attempts to copy it automatically, and includes a selectable URL and **Copy link** button when clipboard permission is unavailable.

Anyone with `/share/<random-id>` can view the latest saved title and LaTeX source without an account, compile locally and export `.tex` or PDF. The separate viewer has no draft writes, account sync, rename, delete or editing controls. Links grant read access only: existing document write APIs still require the owner's session and mutation origin. Treat the URL as a bearer secret; recipients can keep exported copies.

The additive `document_shares` table stores one 256-bit random share ID per account document, with a creation timestamp and cascading document foreign key. `POST /api/documents/:id/share` creates or reuses the owner's link; `DELETE /api/documents/:id/share` revokes it (owner session and origin required). `GET /api/shares/:shareId` returns only title, source and update time, with `no-store` caching; revoked/deleted or invalid links return 404. Creating a share after revocation generates a new ID. Revocation prevents future reads, not copies already downloaded.

## Browser compilation and limits

The asynchronous early HTML module also runs while application CSS is loading. The pdfTeX worker prepares a fixed common starter-package subset alongside WASM/format initialization: 44 already-shipped allowlisted files, 746,722 decoded bytes, at most four package streams, 192 KiB per file and 1 MiB total decoded data (plus bounded transient stream/copy buffers). These bytes are handed directly to the pinned package adapter and released when consumed; it does not fetch them again synchronously. This trades bounded temporary worker memory and speculative local downloads on other pdfTeX documents for avoiding the starter document's serial package waterfall. Other packages remain demand-loaded; native engines remain lazy. Preparation errors are explicit and all preparation stays outside the compile budget.

Real SwiftLaTeX pdfTeX WASM, not HTML printing or math-only rendering. On direct `/#workspace` and valid document-permalink visits, a tiny independent HTML module starts one dedicated classic Worker before React or the app bundle finishes loading. The app adopts that worker, including its pending or completed readiness, without a second engine/format request. Project browsing does not start a compiler; opening a workspace from projects warms it normally. Monaco remains lazy behind the editable text fallback, and PDF.js loads only for a PDF. An unclaimed worker is released on page exit; early loading errors are reported as browser warnings and the app can retry. The pdfTeX worker posts a `started` message before loading anything. If none arrives within 10 seconds, the app replaces the worker once. This handles a worker that is held paused before its script is fetched, for example when a DevTools/CDP client such as an editor-integrated browser, debugger or automation tool auto-attaches with `waitForDebuggerOnStart` and misses that worker. If the replacement is also held, the app reports a clear error instead of waiting indefinitely. Compilation makes two passes. The pdfTeX worker loads once per page session and stays warm across compiles and document switches (no new WASM, format or package fetches); SwiftLaTeX restores its post-startup heap snapshot before every run and each job flushes `/work` first, while the shared package cache, `/tmp` and other directories are read-only to documents, so no aux, output or written files leak between documents. Memory stays bounded by the pinned package manifest. One job at a time; Cancel/supersede rejects the old job immediately without reloading the engine, and the next document starts once the superseded TeX run returns (stale results are dropped). A superseded run that does not return within a short bound (0.75-3 s), a compile timeout or an engine crash terminates that worker and rewarms a replacement in the background. The 60-second cumulative compile deadline starts only once WASM, the format and requested fonts are ready; local package downloads and native PDF-converter initialization pause it. Each loading phase has a separate five-minute deadline with an explicit engine-loading error, not a compile-timeout error. Optional native (XeTeX) workers remain single-use and are terminated after success/failure, releasing their heap. PDF blob URLs are revoked on replacement/switching.

The format downloads asynchronously alongside the runtime's existing streaming WASM instantiation, rather than on the first synchronous typesetting request. Build-generated gzip formats have SHA-256-addressed filenames and one-year immutable cache headers; Streaming gzip decoding in the dedicated worker restores the exact pinned format bytes without blocking the editor. Original format files remain available for older clients. The build regenerates compressed assets and their lookup/hashes before packaging source. The worker hands the format bytes to the pinned runtime without another fetch and releases the temporary reference after use. Native font preparation and XeTeX startup run concurrently; XeTeX remains lazy and its converter still executes sequentially to avoid keeping both heaps alive. No extra persistent binary/module cache or heavy project-page preload is installed: the browser HTTP/WASM cache already reuses assets without duplicating their storage. Results expose `initializationMs` (initial readiness wait), `loadingMs` (all non-typesetting preparation, including later package/converter waits), `compilationMs` (cumulative typesetting/conversion work) and `totalMs`; loading and compilation sum to total. A previously warmed engine has zero initial readiness wait.

The preview uses lazy, self-hosted **PDF.js 6.4.299** to render the actual compiled PDF. Trackpad pinch (Ctrl+wheel) and two-finger touch pinch scale existing page pixels during the gesture, then sharpen visible pages after a 180 ms pause; zoom never compiles or fetches the PDF again. Scrolling is the browser's own `overflow:auto` scrolling, so iOS/macOS/precision-touchpad momentum is native: plain wheel and one-finger touch input are never prevented or script-driven (`touch-action: pan-x pan-y`), only Ctrl/Cmd+wheel, Safari gesture events and two-finger touch are captured for zoom. A modifier pressed during an inertial wheel tail continues scrolling instead of zooming. Lazy re-renders never move the scroll position, and a replacement PDF waits until scrolling (including momentum) is idle, then adopts the latest position before swapping in. Zoom buttons and focused-preview Ctrl/Cmd+plus/minus/0 provide keyboard alternatives. Zoom is bounded to 25-400%. Once zoom settles, pages are laid out in real CSS pixels snapped to whole device pixels, and each canvas backing store equals `round(css size × devicePixelRatio)` (DPR 1, Windows 125%, Retina and iPhone 3x alike), so text is not resampled. Each viewer retains at most three visible-page canvases of up to six million pixels (three million when `navigator.deviceMemory` ≤ 2 GB); larger zooms instead keep a one-million-pixel backdrop plus one sharp viewport-sized detail tile per visible page (capped at 12/6 million pixels), with one temporary replacement during sharpening. A PDF handoff briefly keeps a second bounded viewer alongside the last good one. Very tall viewports can show unloaded paper outside that bound until scrolled. Rasters look soft only while a gesture is moving or until a scrolled-into-view detail tile refreshes after the 180 ms pause. The preview supports up to 1,000 pages and keeps the last good PDF while a new one loads. Reduced-motion disables the replacement fade; pinch tracks fingers directly without an animated zoom transition. **Open PDF** opens the original PDF in the browser's native viewer for text selection, search, links and native accessibility; **Export PDF** remains available if rendering fails. Browser zoom outside the PDF pane remains browser-controlled. PDF.js code/worker load only with a compiled preview, and its CMaps, standard fonts and WASM codecs are served locally, never from a CDN.

The included subset covers the tested `article` (10/11 pt), `report` and `book` (10 pt) classes; `fontenc` with T1 and Latin Modern; `latexsym`, `fullpage`, `titlesec`, `marvosym`, `color`, `verbatim`, `enumitem`, `hyperref`, `fancyhdr`, English `babel`, `tabularx`, `amsmath`, `amssymb`, `geometry`, and `glyphtounicode`; plus the Computer Modern fonts exercised by the fixtures. This is **not a full TeX Live installation**. Arbitrary packages, font uploads, full Unicode script support, shell escape, source assets, and uploaded bibliographies are unsupported. Missing packages return compiler logs. `scripts/bundle-tex.mjs` and `scripts/bundle-native-tex.mjs` are explicit maintainer asset-acquisition tools; the deployed application never downloads additional packages or contacts that mirror.

### Google Fonts in the PDF

The native/fontspec engine also bundles xcolor 2.12 and the basic PGF/TikZ 3.1.5b drawing subset, including overlay nodes, page anchors and paths. Optional TikZ libraries remain unsupported unless explicitly bundled. These packages are local pinned assets; compilation never downloads TeX packages. Their corresponding source archives and licenses are linked in the compiler notice.

Conventional missing-font references such as `\newfontfamily\body[Path=fonts/,RawFeature={-kern,-liga,-clig}]{Roboto-Regular.ttf}` can use a **virtual Google font filename**. The accepted grammar is a PascalCase ASCII family followed by `-Regular.ttf`, `-Bold.ttf`, `-Italic.ttf` or `-BoldItalic.ttf`; lowercase-to-uppercase boundaries become spaces (`CrimsonPro` means `Crimson Pro`, `OpenSans` means `Open Sans`). Only the literal optional `Path=fonts/` is accepted, and it is removed from the transient compilation input, never accessed or fetched. Unknown families, ambiguous/other filename forms, directories, URLs, and computed names fail explicitly. These references request the exact resolved Google family/weight/italic face, not a different family or style. RawFeature accepts only literal signed `kern`, `liga`, and `clig` switches and passes them unchanged to XeTeX.

This does not import or replace existing local font files: the text-only app cannot access sibling files on disk. Use virtual references only when the original assets are missing and Google family/style resolution is intended. A downloaded Google face need not be the same historical binary/version as an absent original; historical metrics/layout equivalence is not guaranteed. The stored/exported source remains unchanged.

Use literal `fontspec` declarations to select **any Google Fonts family that supplies a compatible static TrueType face**, not just a curated list:

```tex
\documentclass{article}
\usepackage{fontspec}
\setmainfont[BoldFont={Roboto Bold}]{Roboto}
\newfontfamily\crimson{Crimson Pro}
\newfontfamily\lato{Lato}
\begin{document}
Roboto regular. \textbf{Roboto Bold.}
{\crimson Crimson Pro.}
{\lato Another Google Fonts family.}
\end{document}
```

Supported explicit commands are `\setmainfont`, `\setsansfont`, `\setmonofont`, `\newfontfamily\name` (or `{\name}`), and `\fontspec`. Standard fontspec options can appear **before or after** the braced family, or in both positions. `UprightFont`, `BoldFont`, `ItalicFont`, and `BoldItalicFont` select family/style names; empty non-upright faces disable that style instead of downloading a replacement. Exact Google family names take precedence; when no exact family exists, style suffixes `Thin`, `ExtraLight`, `Light`, `Regular`, `Medium`, `SemiBold`, `Bold`, `ExtraBold`, `Black`, and `Italic` resolve to the underlying family/style. Thus `Archivo Black` remains the actual family, while `Roboto Bold` resolves to Roboto at weight 700.

Imported documents can use unconditional top-level literal `\newcommand`, `\renewcommand`, `\providecommand`, `\def` or `\gdef` font-name definitions before their declarations. Zero-argument aliases may reference another such macro (up to eight aliases; at most 128 scanned definitions). For example:

```tex
\newcommand{\mainfont}{Roboto}
\def\boldfont{Roboto Bold}
\defaultfontfeatures{Ligatures=TeX}
\setmainfont{\mainfont}[BoldFont={\boldfont},Scale=1.05]
\newfontfamily{\crimson}[LetterSpace=1]{Crimson Pro}
```

Safe features are preserved in the transient compile input: `Scale` (0.1-10 or `MatchLowercase`/`MatchUppercase`), `LetterSpace` (-5 to 20), `Ligatures` (`TeX`, `NoTeX`, `Common`, `NoCommon`, `Required`, `NoRequired`, `Rare`, `NoRare`, `Discretionary`, `NoDiscretionary`, `Historic`, `NoHistoric`), `Numbers` (`OldStyle`, `Lining`, `Proportional`, `Monospaced`, `SlashedZero`, `NoSlashedZero`), `Kerning` (`On`/`Off`), hexadecimal `Color` (6/8 digits), literal `Script`/`Language`, `Renderer` (`OpenType`/`ICU`), and the bundled `Mapping=tex-text`. Braced comma-separated Ligatures/Numbers values are accepted. These same features work in `\defaultfontfeatures` and `\addfontfeatures`; available OpenType features still depend on the selected font and pinned XeTeX, with fontspec diagnostics in the compile log.

The already bundled `Latin Modern Roman` regular/bold/italic/bold-italic faces use local OpenType assets without any Google request. Loading `fontspec` alone also selects the native engine and its bundled Latin Modern serif/sans/mono defaults (including bold/italic shapes); **a `\setmainfont` declaration is not required by XeTeX or this application**. No Google family is inferred when none was requested. The additional default sans/mono OpenType assets total about 689 KB and load only when actually needed.

The scanner ignores `%` comments, `\verb` and verbatim/listing regions, but is **not a full TeX interpreter**. Macros with arguments, local/conditional/computed definitions, `\edef`/`\let`, names assembled from fragments, paths/URLs other than the documented virtual `Path=fonts/` namespace, font declarations hidden inside macro expansion, unlisted fontspec features and variable-axis controls are unsupported. Unsupported names/settings fail before font requests; the stored/exported source is never rewritten. Bold/italic commands and standard section/title commands conservatively request matching styles for declared families; if a family lacks that requested style, compilation fails explicitly. Specify style options when needed. Missing glyphs/font substitutions also reject the new PDF and preserve the last good preview. Native text shaping is supported by the pinned XeTeX build, but some shaped glyphs/ligatures lack PDF text-extraction mappings; universal Unicode/accessibility/searchability is not claimed.

Only documents loading `fontspec` or using these declarations select the optional, self-hosted **SwiftLaTeX XeTeX** engine. It writes XDV; the self-hosted **DVIPDF** converter embeds actual font programs into PDF. These engines execute sequentially in dedicated cancellable browser workers, never on the server. Source is unchanged in the editor, drafts, D1 and `.tex` export; only a transient compilation copy replaces font declarations with generated local filenames.

The native worker, child adapters, package loader and manifest share a versioned URL query, preventing an older cached manifest from being mixed with revised font support. The unchanged pinned WASM/format assets keep their existing URLs and HTTP cache reuse; this is not an immutable-cache claim. All compiler/font-package downloads remain static `/compiler/*` asset requests, not API proxies.

`GET /api/fonts` accepts only a validated family/style and proxies metadata from a fixed Google CSS endpoint using a TrueType-compatible user agent. This is necessary because Chrome's direct CSS request receives WOFF2, not TeX-compatible TTF. It never receives source or font bytes and never compiles. The frontend downloads only validated `https://fonts.gstatic.com/s/.../v.../*.ttf` URLs, without credentials/referrers or redirects. Only family/style names leave the browser for resolution. Default documents make no font-service/Google requests.

Limits: 10 seconds per font request, a separate five-minute loading-phase deadline and 60 seconds of actual compilation excluding downloads/engine preparation, 16 faces, 8 MiB per face and 24 MiB total. Deduplicated memory/device caches are bounded to 24 MiB and the persistent cache to 16 entries. Persistent writes use Web Locks to preserve the bounds across tabs; browsers without that API use memory caching and report this limitation. Device caching is optional and reports failures through browser warnings; downloaded fonts may need a connection again if evicted. A cancelled/superseded job aborts downloads and releases its worker tree. Unavailable families/styles, unsafe URLs, unsupported formats and missing glyphs produce actionable errors, never a success-shaped substitute.

The cold optional path adds a 22.79 MB format, 3.07 MB XeTeX WASM and 0.70 MB converter WASM, plus glue, required local packages and selected fonts. It is not eagerly loaded for other documents. The largest format remains below Cloudflare's 25 MiB static-file limit. Active memory can exceed 100 MB; sequential engines and worker termination reduce peak/idle memory, but this is not a low-memory guarantee. `tests/fixtures/google-fonts.tex` covers Roboto regular/bold, Crimson Pro and unrelated Lato, with assertions on actual PDF embedded font streams. Test font snapshots have per-file hashes and upstream licenses; `scripts/bundle-font-test-fixtures.mjs` explicitly refreshes them. Set `LIVE_GOOGLE_FONTS=1` to exercise the real service instead of deterministic test responses.

The source pane uses a reusable Monaco Editor with an original LaTeX tokenizer, a high-contrast blue-charcoal theme and native editing contributions, not custom shortcut/edit dispatch. F1 opens the native command palette; the editor context menu also exposes commands. Ctrl/Cmd+F finds, Ctrl+H (Cmd+Option+F on macOS) replaces, Ctrl/Cmd+/ toggles `%` line comments, and Tab/Shift+Tab indents/outdents with two-space indentation. Native undo/redo, line movement/copying, multi-cursor selection, word/subword navigation, line selection and smart selection are available using Monaco's platform keybindings. Ctrl+M (Ctrl+Shift+M on macOS) toggles **Tab Moves Focus**; then Tab/Shift+Tab leaves the editor using browser focus navigation. The loading textarea retains ordinary browser text editing and focus navigation until Monaco is ready.

This is Monaco **0.57.0**, not a full VS Code workbench or extension host. Native word wrapping is on by default, including read-only shared source views, using Monaco's `wordWrap: 'on'` option without changing source text. This package does **not** register VS Code's `editor.action.toggleWordWrap`/Alt+Z command; no custom wrap command, keybinding dispatcher or workbench emulation is installed. OS/browser-reserved shortcuts (for example browser location/bookmark commands, or window-manager multi-cursor combinations) may not reach a web editor. Use F1 or the context menu for registered actions when a key is reserved. LaTeX has syntax highlighting, brackets and line comments, not a language server, formatter or extension-provided IntelliSense.

Monaco text uses 13px on desktop and 14px on mobile, scaling with the root text size; its line-height remains a compact 1.5. The loading fallback matches on desktop and keeps a 16px input on mobile to avoid iOS focus zoom, with matching line spacing; Monaco's hidden mobile input also remains 16px while rendered source stays 14px. Ctrl/Cmd+S and Ctrl/Cmd+Enter are intentional app compilation shortcuts, even when source is unchanged; neither immediately saves to the account. Ctrl/Cmd+Shift+Enter retains native Insert Line Above. Monaco begins loading as soon as the source pane mounts, with an immediately editable plain-text fallback while it loads (also retained with a visible error/retry if loading fails). Only the editor API and selected editing contributions are bundled; unused language services and minimap are disabled. One editor/model is kept for the active document and disposed on switches. Its text worker is self-hosted and never compiles TeX; the dedicated pdfTeX/XeTeX workers perform compilation.

Monaco adds a significant separately loaded editor chunk; production build output reports its exact compressed size. A cold two-pass compile of the bundled T1/Latin Modern résumé-package fixture fetches roughly 27 MB of uncompressed runtime, format and package assets; the 10.36 MB format is the largest individual file, below Cloudflare's 25 MiB per-file limit. Browser HTTP caching avoids repeat network transfer where supported, but a new bounded Worker is created per compile, trading some startup work for lower idle RAM. Active compiler memory can exceed 100 MB. Manual compilation avoids CPU churn. 120 fps/8.33 ms is a design target, not a guarantee on low-end devices. No artificial claim of zero CPU/RAM or universal package support.

Editing remains usable offline while the app is loaded; IndexedDB persists drafts. This version does not install a service worker, so a first visit/reload offline and uncached compiler assets require a connection.

## Page JavaScript API for agents

The loaded page exposes `window.latex`, a frozen API that drives the same React state and actions as the UI. Agents and automation (Playwright `page.evaluate`, DevTools console) can use it instead of DOM snapshots. Run `latex.help()` for every method signature, or `latex.help("replace")` for one; the in-app Help dialog also lists them. Every method returns JSON-serializable data or a Promise that settles when the action has actually completed.

```js
await latex.ready();                       // drafts + sign-in check loaded
latex.list();                              // [{ id, cloudId, code, url, title, local, cloud, updatedAt, dirty, current }]
await latex.open('Alpha paper');           // id, cloudId, 8-character code, /documents/... URL, list key or exact title
latex.read({ from: 1, to: 20, numbered: true });
latex.replace('Old title', 'New title', { all: true });   // edits go through Monaco: undoable + autosaved
latex.replaceLines(3, 4, '\\usepackage{amsmath}');
const result = await latex.compile();      // { ok, status, errors, warnings, timings }
latex.log().errors;                        // parsed [{ message, line, context }]
await latex.preview();                     // resolves once the new PDF is shown, with page count
latex.timings();                           // engine startup, compile, local and account save ms
await latex.save();                        // device save, then awaited account save when signed in
const off = latex.on('compile', detail => console.log(detail));
```

Coverage: `status`, `list`, `current`, `open`, `create`, `rename`, `remove` (requires `{ confirm: true }`), `read`, `find`, `setSource`, `replace`, `replaceLines`, `insertLines`, `append`, `undo`/`redo`, `save`, `compile`, `cancel`, `preview`, `log`, `timings`, `pdf`, `exportTex`, `exportPdf` (base64, Blob or download), `show`, `livePreview` and `on` (`change`, `document`, `compile`, `preview`, `save`, `error`).

`create` resolves after device persistence/selection as before; account sync runs in the background. `remove` and `save` await their account requests, but do not block operations on other documents. Removing a non-current document never switches away from your current work.

The API costs nothing while unused: no polling, timers or extra requests. Calls use only the requests the equivalent UI action makes. Account operations use the existing same-origin session cookie and owner-scoped endpoints. The API never exposes session tokens or credentials, and it does not open sign-in prompts or `confirm()` dialogs. Opening an account copy over an unsynced device draft is declined unless `replaceDraft: true` is passed.

## Database schema and Cloudflare deployment

`server/schema.js` is the authoritative Drizzle schema. `npm run db:generate` generates reviewed SQL and snapshots in `migrations`. `npm run db:check` checks the Drizzle journal and fails if schema changes need a new committed migration. Do not use schema push/reset in production. Migrations use forward-only expand/contract changes: deploy additive schema before code that depends on it; remove obsolete columns in a later PR once all deployed code no longer reads them.

Use the authenticated Cloudflare account with `cf auth whoami`. The checked-in `.github/workflows/quality.yml` runs tests on each PR and deploys only after a PR merges into `master`: it applies D1 migrations **before** code deployment and serializes production updates. Do not run manual production deploys or remote migrations. GitHub Actions needs the repository Actions secrets `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`. The account-owned API token must be non-expiring (leave TTL empty), scoped only to Workers Scripts Edit and D1 Edit in the KhanhhNe account, and have no IP restriction so GitHub-hosted runners can use it. Before migrations, CI uses Cloudflare's [account-token verification endpoint](https://developers.cloudflare.com/api/resources/accounts/subresources/tokens/methods/verify/) to confirm the token is active and has no `expires_on` value; it never prints the token or raw API response.

For routine rotation, create a replacement with the same least-privilege, non-expiring policy, update the GitHub Actions secret `CLOUDFLARE_API_TOKEN` through the repository's secret settings, and wait for the merged-master verification/deployment workflow to succeed before revoking the old token in Cloudflare. If exposure is suspected, replace the secret and revoke the exposed token immediately, then rerun deployment verification. Never put the token in source, logs, command arguments, `.env`, or frontend assets. Keep production credentials in GitHub/Cloudflare secrets only. Configured URL: `https://khanhhne-latex.khanhhne.workers.dev`. AI is deferred; the application does not send the local `.env` key or require a production AI secret.

## Separate, isolated worktrees

```powershell
git worktree add ..\KhanhhNeLatex-auth -b feat/auth
cd ..\KhanhhNeLatex-auth
npm ci
npm run db:local
npm run dev:worktree
```

`dev:worktree` selects an available localhost port, creates a per-worktree `.wrangler/worktree-state` local D1 store, and supplies `APP_ORIGIN` as a local Wrangler variable. It ignores `.env`, removes Cloudflare credentials from Wrangler's process environment, and does not modify `.dev.vars`. Run `npm run db:worktree` in each worktree to initialize its isolated database. No remote database or production credentials are used by local development. Use a single `dev:worktree <port>` argument to choose a port.

## Tests and collaboration

Every pull request to `master` runs `Quality / verify`: npm install, browser setup, unit and end-to-end tests, migration consistency, and production build. Merge a ready change with `gh pr merge <number> --auto --squash` after the check passes. Resolve conflicts/rebase against current `master`, rerun checks, and update the PR. No human approval is required by the repository ruleset, but status checks cannot be bypassed.

Before handing off/merging a change, review the complete diff; check missing/error paths, authorization, input sizes and text-only handling; prove actual browser-worker PDF compilation and export where relevant; test mobile and keyboard behavior; inspect network requests to ensure editing is offline/local; verify browser worker/object URL release and bounded job lifetime; test D1 ownership and stale revisions; review new SQL for expand/contract compatibility; and confirm `git status --ignored`, `git check-ignore .env`, build asset contents, and secret-scan results. A passing build alone is not functional or security evidence.
